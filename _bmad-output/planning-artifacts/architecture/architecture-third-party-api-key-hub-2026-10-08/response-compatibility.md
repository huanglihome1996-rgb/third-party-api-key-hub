# v1 请求与响应兼容

本文件是 [架构](ARCHITECTURE-SPINE.md) AD-13 的强制 companion，固定 PM-04 的修订。完整命令/schema/虚构样例仍由 Story 1.1 形成，代码只由 contract/v1 拥有。

## 分开的校验策略

| 边界 | 校验与扩展规则 |
| --- | --- |
| 请求参数／IPC 请求 JSON | 未知操作、未知／重复字段、错误类型、非法 ID、超限体和多对象输入均拒绝。新增请求能力须显式支持；不承诺旧服务接受未知新命令。 |
| 取密成功响应 | 保持 identity／credentials／status 三组及全部既有必填字段。仅 identity、status 和 status.app／status.shop 的各 type 状态条目允许新增可选非敏感元数据；这些对象是 v1 固定的扩展位置。顶层和 credentials 仍严格。 |
| 凭据组合 | credentials 仅 app／shop；条目仍为 type／value，必须与受控 profile 定义的完整必需组合对应。未知秘密 type、重复项、额外秘密字段、缺少必需项和跨对象组合拒绝，不因元数据扩展而放行。 |
| 失败响应 | 严格只有 error／安全 message；额外字段、秘密、畸形或截断响应均拒绝。失败不进入成功凭据输出路径。 |
| 其他成功结果 | Story 1.1 逐操作命名非敏感元数据扩展位置；未显式允许的位置仍严格。不得在 v1 同主版本扩大秘密输出范围。 |

所有 JSON 对象，包括扩展位置，仍拒绝重复字段。已知字段的类型、含义、必填性、状态 type/generation 对应关系保持校验；不能把整个响应当作任意 JSON。更改既有字段／类型／含义、增加必填要求或扩充秘密编码需升级主版本。

## CLI 输出

服务只可在上述扩展位置添加非敏感字段。旧 CLI 完整读取后校验已知契约，忽略允许位置的未知可选元数据，并从已验证字段重建 stdout，不能原样转发未知字段。新 CLI 可以在同版本 schema 明确已知的新可选字段后输出它。credentials 只从经验证的业务凭据白名单构造，禁止未知秘密透传；错误对象无任何凭据。

服务结果无效时在输出业务秘密之前拒绝；完整读取及一次写出是应用层提交边界，不宣称损坏管道或进程终止可以保证操作系统层原子输出。写出开始后的 I/O 故障不得追加第二个 JSON 或声称服务操作回滚；预算／诊断按 Story 1.1 的非敏感传输错误规则处理。

## 兼容验收

1. 旧 CLI＋新 hubd 在 status 条目新增虚构可选非敏感字段：成功，已知凭据与状态语义不变，旧 CLI 不透传未知字段。
2. 已知字段类型改变、重复 JSON 字段、未知 credential type／字段、重复 type、错误响应夹带值、截断响应：失败且未输出任何业务秘密。
3. 请求含未知字段仍拒绝；成功响应在未允许位置新增字段也拒绝。
4. 新 schema 的 generation 与对应 type 绑定，旧值失效报告使用该快照引用。此基线在首次 CLI schema／实现之前固定，不伪称已有部署客户端已通过兼容测试。
