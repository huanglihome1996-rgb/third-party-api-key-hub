# 运行与恢复契约

本契约实施用户于 2026-10-09 确认的 Epic 3 平台无关/Docker范围。生产 OpenBao身份与恢复、真实 Seller和Ubuntu/systemd/双架构实机验收不因本文件完成而通过；不改变一期产品及运行指标。

## 一致边界与文件所有权

普通 application 请求及 local.reject 从进入到其 deferred audit 结束均持外层运维读门。备份/保留/恢复开放取得写门，等待既有业务与审计完成；写门期间不允许新领域请求或边界审计写入。运维自身避免读→写升级死锁。内层领域门与 SQLite revision CAS 保留；所有持久领域变更仍通过 application。

两库使用 SQLite 快照机制，不能复制活动数据库文件。冻结/排空后、快照开始前的 UTC 时间是 manifest.created_at 和 RPO可恢复状态边界；业务 revision 与两库数据属于这个共同边界。备份自身审计可能发生在快照之后，属于明确的边界外事件，不能假称已在包中。既存审计写入缺口以 audit_gap 保留，不补造丢失事件。

快照先在受控备份根的私有 staging 目录生成；文件0600/目录0700，固定文件 business.sqlite、audit.sqlite、manifest.json。数据库完整性及文件 hash 校验完成，文件/目录同步后按唯一 backup_id 在同一文件系统原子发布，失败不替换旧备份，未发布目录不算可恢复状态。活动 SQLite 不位于网络文件系统。

manifest 只含格式、模式、实际 schema、构建版本、非敏感 fixture配置绑定、共同时间/revision、审计缺口、文件SHA256和独立密钥指纹/版本引用；禁止 key、SecretID、Token、明文和密文包进入 manifest。哈希是损坏检测，不代替可信备份来源/权限。现有 schema 只为实际恢复控制字段迁移，不预建平台实体。

## 密钥恢复材料

业务备份不包含开发 key。fixture key 使用独立0700目录与0600文件；恢复操作要求明确的现有 key路径，先验证指纹和全部当前凭据的用途/中心目标/type/generation绑定解密，无输出明文。缺 key不生成，错 key拒绝，存储和独立材料位于受控本地主机权限边界。

真实 OpenBao材料必须单独列出必要Transit版本、身份/策略与恢复步骤并实际验证；本轮只演练fixture材料，不声称生产密钥生命周期/旧版本可解证据已经取得。future平台 pending包与operation/App/epoch/profile快照的保护及未结操作处理继续由Epic2及SQ-3交付。

## 一年审计保留

令 now 为可信服务 UTC 当前时间，cutoff 为 `min(now.AddDate(-1,0,0), now-366*24h)`；只删 `event.Time < cutoff`，等于边界保留。这一保守规则不少于一年，覆盖闰日归一化。全部待清理记录须可解析；未来事件、损坏记录或倒退时钟禁止清理。最近清理时间随审计元数据持久化，清理在单审计事务完成，失败不部分删除。

每日任务执行一致备份与保留，使用同一门及固定服务目录；计划未运行、写入/存储失败不算备份成功。CLI也可显式调用，不接受客户端路径或时钟。失败仅发固定枚举白名单告警并降级健康，不回滚已提交业务。不承诺同磁盘故障零丢失。

系统拒绝、服务拒绝与client自报来源不同：只有已到达服务的事件由此审计；公开edge、连接前主机拒绝的采集仍须SQ-4真实验证。不得收集argv、URL query、请求/响应体、秘密、底层平台原文或密文。

## 恢复状态机

离线恢复只接受完整允许文件集，先校验普通文件/禁止链接和路径逃逸、hash、schema、模式、构建/配置绑定、独立key和逻辑凭据绑定。目标必须不存在；使用与daemon一致的排他边界，不能覆盖运行实例。临时目录失败清理不暴露半成品。

恢复关闭状态写入业务库后才发布目标目录；服务重启仍关闭取密。非敏感查询和受控管理可用于复核，无平台调度能力不伪造运行中的刷新。恢复开关与凭据自身disabled正交。

manage取得 recovery.status/credential.status，核对当前账户、完整归属和当前fixture值，recovery.open须带当前expected_revision、三项显式核对声明及精确覆盖所有逻辑凭据的expected_generation引用。服务逐一验证当前绑定及安装必需组合；提交前复核manage，事务保存开放后才发布内存状态。并发变更使旧revision复核失效。

停用/过期目标可保留其决定与版本证据；开放不把它们变成可用。缺链/缺必需项/错误key和过时复核保持关闭，失败无部分明文。真实平台current值/旧refresh、未结operation和恢复资格复核未实现时不提升为生产可开放证据，禁止盲重放平台任务或从审计缺口推造资格。

## 运行测量与验收

本地目标：10并发完整CLI→Unix身份→application完整映射/状态→保护后端解密→响应验证→完整输出；nearest-rank `ceil(0.95*n)` p95≤2s。主样本不剔除冷/慢/失败请求；分别报告全部、成功、失败样本，冷启动到健康和维护负载另记。15秒协议deadline不是2秒达标。禁止跨请求秘密缓存、跳过KMS、延长期限或HA达标。

benchmark用隔离虚构组合，仅内存验证输出，报告延迟/错误枚举/环境，不写stdout秘密。fixture无真实KMS，生产“健康KMS”须提供隔离真实后端健康/延迟/错误及样本时间窗；未得到该证据主生产目标仍未验证。

RPO以故障UTC时间减最新完整、可解、配套快照的共同冻结时间，要求≤24h；每日定时器触发本身不是RPO证据。RTO以故障到复核后显式开放的连续耗时，生产包括人工核对、必要平台复核/重授权及材料获取，要求≤4h，不暂停计时排除等待。fixture drill仅报告自动恢复耗时和虚构RPO，不能称为人工生产RTO达标。
