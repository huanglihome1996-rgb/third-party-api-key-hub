# 产品简报：第三方平台 API 凭据管理中心

> 本页保留原产品简报基线及当时交接事项；后续已接受的本地主机 CLI、OpenBao 与状态/兼容规则以 [PRD](../../prds/prd-third-party-api-key-hub-2026-10-08/prd.md) 和 [SPEC](../../../specs/spec-third-party-api-key-hub/SPEC.md) 为准。原“待确认”不重开现行决定。

## 执行摘要

本项目面向内部系统，建设一个统一的第三方平台接入与 API 凭据管理中心。系统围绕平台 App、外部平台店铺、品牌和内部系统店铺建立稳定关联，负责第三方授权凭据的获取、保存、刷新、撤销和查询。

首期接入 TT（TikTok Shop），支持店铺授权和手工导入凭据。长期目标是让内部系统通过统一的品牌或店铺身份获得第三方平台连接能力，不必分别实现授权回调、Token 生命周期和凭据映射。

## 首期范围

- 登记第三方平台和平台 App，建立外部店铺、品牌、内部店铺和安装授权的领域模型。
- 完成 TikTok Shop 的店铺授权发起与回调流程，支持手工导入 API Key／Token。
- 管理 App 级和店铺安装级凭据的保存、验证、刷新、撤销和查询。
- 维护外部店铺到品牌、品牌到内部店铺的映射，并校验归属唯一性。
- 提供 Go 编写的 Linux 常驻服务、`systemd` 配置及可复现的构建和打包命令。
- 提供 JSON-first CLI 和基础访问审计，有权限的调用者可按品牌、内部店铺或外部店铺查询完整凭据。
- 凭据查询／导出仅面向可信内部环境，JSON 直接返回完整明文 API Key／Token，不做查询结果脱敏，不开放公网匿名取密。

## 后续范围

- CLI 的钉钉身份验证。
- 更多平台适配器及凭据代理调用能力。
- 多租户、角色权限和更细粒度的终端授权策略。
- 商品、订单、广告等第三方业务数据同步。
- 将 CLI 独立分发到用户终端，以较少的依赖项、稳定的退出码和 JSON 输出支持查询，并明确敏感字段控制。

## 问题

第三方凭据通常产生于平台 App 与店铺的安装授权过程，不只是孤立的 API Key。

当关联关系和凭据分散在平台控制台、环境变量或业务代码中，内部系统难以判断凭据对应的店铺和品牌，也难以统一处理授权过期、刷新、撤销、审计和新增平台接入。

## 服务对象

- **集成运维人员**：登记平台 App、发起店铺授权、处理失效授权和维护映射，查看授权状态、失效时间和归属关系。
- **内部业务系统和自动化脚本**：通过统一接口或 CLI 按业务归属获取可用凭据，并调用第三方 API。

## 方案与领域关系

系统以安装授权作为 App 与外部店铺之间的核心关联：

```text
第三方平台
  └─ 平台 App
      └─ Installation / Authorization
          └─ 外部平台店铺
```

关系约束如下：

- 平台 App 与外部平台店铺是多对多关系，通过安装授权关联。
- 外部平台店铺与品牌是多对一关系，一个外部店铺只能属于一个品牌，一个品牌可以对应多个外部店铺。
- 品牌与内部系统店铺是双向一对一关系。

以安装授权而非单个 API Key 表达 App 与店铺之间的连接，独立追踪各安装授权的凭据状态。将外部店铺、品牌和内部店铺的映射纳入查询链路，减少业务系统自行拼接关联关系的需要。

## 技术与安全约束

- 常驻服务使用 Go 承接平台授权回调，CLI 用于查询可直接调用 API 的凭据；两者共享领域模型、平台适配器、授权状态和凭据管理核心，适配器隔离第三方平台的授权和 API 差异。
- Linux 部署不绑定单一安装包格式，常驻服务由 `systemd` 管理。
- CLI 输出稳定、机器可读的 JSON，适合 AI 和脚本解析。
- 本地开发支持环境变量注入；生产环境预留专用密钥管理服务边界。
- 真实凭据不得进入源码、Git、日志、测试数据或错误响应；正常查询的明文返回不放宽日志和错误响应的脱敏要求。

## 成功标准

- 新增一个平台适配器时，不需要修改核心的店铺、品牌、内部店铺和安装授权模型。
- 一个 App 可以关联多个外部店铺，一个外部店铺也可以关联多个 App，且每个安装授权的凭据状态独立可追踪。
- 每个外部店铺只能关联一个品牌，每个品牌与一个内部系统店铺保持双向唯一关系。
- 授权回调可安全、幂等地完成凭据保存和关联关系更新。
- 首期 CLI 按业务归属查询时输出稳定、机器可读的 JSON，并直接返回完整明文 API Key／Token，用于直接调用第三方 API。
- 首期凭据查询／导出仅在可信内部环境可用，不开放公网匿名取密。
- 凭据不进入源码、Git、日志、测试数据或错误响应；生产环境支持专用密钥管理服务。
- Go 服务可以通过构建和打包命令部署到 Linux，并由 `systemd` 管理运行。

## 待决事项与后续交接

- **平台接入设计**：[ASSUMPTION] 店铺授权采用 OAuth，实际协议与接口待核实；授权回调的网络可达性需单独设计，不能从凭据查询／导出仅限可信内部环境这一约束中推定。
- **架构**：确定首期可信内部环境的访问控制方式和生产密钥管理服务。
- **交付规划**：确定 Linux 目标发行版及后续 CLI 终端分发渠道。
