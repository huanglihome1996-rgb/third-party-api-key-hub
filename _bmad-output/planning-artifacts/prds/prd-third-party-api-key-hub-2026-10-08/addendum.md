# 已确认技术约束与后续设计入口

本补充承接定稿产品简报和后续用户确认的技术选择，供架构与平台接入设计引用；未确认的技术细节保持待设计，不表示技术设计已经完成。

现行技术方案已由 [final 架构](../../architecture/architecture-third-party-api-key-hub-2026-10-08/ARCHITECTURE-SPINE.md) 采用；本文件的原技术交接事项保留其历史来源，当前未完成项以 [实施门槛](../../../specs/spec-third-party-api-key-hub/implementation-gates.md) 为准。2026-10-08 修订补充版本证据/业务失效上报、响应扩展与待处置结果保护，不改变首期范围。

## 已确认技术约束

- 使用 Go，交付 Linux 常驻服务与 CLI，共享领域模型、平台适配器、授权状态和凭据管理核心。
- 服务承接第三方授权回调与自动刷新，平台适配器隔离授权和 API 差异；本中心不建设首期 Web 管理界面。
- 提供可复现 Linux 构建与打包命令，支持 systemd，不绑定单一安装包格式。
- 本地开发支持环境变量注入；生产采用架构确认的 OpenBao Transit，不以 Vaultwarden 替代首期密钥后端。
- CLI 采用 JSON 输出，首期仅在服务 Linux 主机通过受控账户管理与取密；独立终端分发属于后续范围。

查询、导入、映射、停用恢复及审计的产品规则以 [PRD](prd.md) FR-1 至 FR-12 为准，技术设计不得放宽该边界。具体 JSON、命令和状态编码由 CLI 设计确定；账户／存储权限、缓存、并发、刷新调度、审计存储与告警由架构和接入设计落实。

## 手工导入的 CLI 输入约束

手工导入同时支持隐藏凭据值的交互输入，以及从标准输入读取的非交互脚本模式。隐藏输入不能回显凭据值；交互提示使用标准错误，标准输出保留 JSON 操作结果。两种模式均遵守 PRD 的凭据保密要求，不要求将真实凭据值作为命令行参数或写入脚本源码。

标准输入的具体格式、读取结束条件、缺少必填内容时的处理、隐藏交互机制和中断行为由后续 CLI 设计细化；非交互模式不得因缺少内容而进入交互等待。设计和使用示例仅使用虚构凭据，并避免通过带有真实凭据字面量的 Shell 命令构造输入。

[PRD 决策状态与技术交接](prd.md#决策状态与技术交接)维护 Q-1 至 Q-11 的当前状态；文末责任表规定复核条件。数据库、密钥后端、Linux 与传输协议已由架构采用；完整 CLI schema、平台 profile、当前值/待处置包编码及实际部署/恢复仍需设计或验证，按实施门槛路由。

## 后续自建 Vaultwarden 集成

**用户已确认的方向（2026-10-08）**：接入自建 Vaultwarden 密码管理平台，密钥更新后自动推送到该平台；平台内谁可以访问或查看由 Vaultwarden 决定。该能力属于后续范围，产品边界见 PRD 的 PF-1、PF-2。

Vaultwarden 平台查看权限不授予用户首期本地 CLI 权限，也不表示该平台已被选作本中心生产密钥存储后端。

**后续设计入口**：

- 核实目标 Vaultwarden 部署支持的集成方式，以及自动写入所需的客户端、账户、加密与授权要求；当前没有核实具体接口或选定 SDK／CLI。
- 明确密码管理条目与平台 App、外部店铺、安装授权及凭据的映射和组织方式。
- 明确推送范围与首次同步、更新事件、失败重试、更新顺序、手工修改冲突、撤销和删除传播规则；这些行为尚未形成用户决定。
- 为同步账户选择受控的访问与密钥管理方式，推送和失败诊断继续遵守真实凭据不得进入源码、Git、日志、测试数据或错误响应的约束。

问题统一记录在 Q-11，待后续 Vaultwarden 集成设计时处理，不增加首期验收条件。

## TikTok Shop 官方资料核对（2026-10-08）

本节记录官方资料提供的平台能力线索，供平台接入设计继续核实；不替代目标市场、应用类型和实际接口的联调。以下事实来自研究子任务读取的官方页面可读内容，尚未使用真实平台 App 验证。

- [Create your App](https://partner.us.tiktokshop.com/docv2/page/create-your-app) 描述 Seller 授权入口的 US／ROW 差异、回调授权码与 Token 兑换流程，以及独立的刷新接口。兑换参数包括 `app_key`、`app_secret`、`auth_code` 和 `grant_type=authorized_code`。目标市场与应用类型须在接入设计中确认，不能直接套用其他 TikTok 产品的登录协议。
- [Affiliate integration](https://partner.tiktokshop.com/docv2/page/affiliate-integration) 的 Seller onboarding 描述授权后通过 Get Authorized Shops 核对 Token 与店铺映射，并取得 shop ID。该页面处于 Affiliate 集成语境，目标 App 的适用性、权限和完整响应字段仍需核实。
- [Common parameters](https://partner.tiktokshop.com/docv2/page/678e3a4278f4c20311b8b57e) 说明 `shop_cipher` 是加密店铺标识，其使用要求随接口而异；202309 起 access token 通过 `x-tts-access-token` 请求头传递。外部店铺的业务标识与接口使用的 `shop_cipher` 应由适配器明确区分。
- [Creator authorization guide](https://partner.tiktokshop.com/docv2/page/678e3a362dccb8030ea6f98c) 描述 Creator 授权；Seller 与 Creator 身份及凭据不能混用。本项目首期接入的是店铺，不能据此引入 Creator 授权需求。

**仍未核实**：Seller 平台撤销接口、具体 Token 有效期、刷新后的轮换与旧凭据有效性、Get Authorized Shops 完整响应契约，以及回调校验、失败重试和网络可达性要求。部分 API 页面需要 JavaScript 渲染，现有可读资料不足以确认这些细节。

用户随后已确认首期仅做本地停用，因此 Seller 平台撤销接口的核实不阻塞首期本地撤销实现，也不表示该接口已核实或需要接入。

Q-7 已取得官方资料线索，转交平台接入设计者在 TikTok 接入 Story 编写前核实；PRD 的 A-2 已标明该复核条件，不作为已核实协议。接入设计应复核目标市场与 App 类型对应的官方版本，并将确认结果同步回 FR-5、FR-7、FR-8 的验收规则。
