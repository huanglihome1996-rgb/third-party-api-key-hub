# 早期输入与当前需求对齐

核对输入为 [早期项目简报](../../../../docs/project-brief.md)，对应当前 [PRD](prd.md) 和 [交接补充](addendum.md)。[定稿产品简报](../../briefs/brief-third-party-api-key-hub-2026-09-29/brief.md)及其后续用户决定优先；用户已确认 [批量推荐决定](recommended-decisions.md) R-1 至 R-9。

结论：早期输入中仍有效的产品目标、安全边界与扩展要求均已覆盖，无重要需求遗漏。早期未决事项已形成产品决定，或明确交接给技术设计；不要求在 PRD 定稿前完成平台联调。

| 早期输入 | 当前覆盖或替代依据 | 处理结果 |
| --- | --- | --- |
| 安全配置、验证、管理不同平台的 API 凭据 | 产品目标；FR-1、FR-5 至 FR-8；NFR-1、NFR-4 | 已覆盖；首期限定 TikTok Shop，后续可新增适配器。 |
| 定义统一的平台适配器接口 | NFR-4、SM-8；交接补充“已确认约束”明确平台适配器隔离授权与 API 差异，并由 Go 服务和 CLI 共享核心 | 扩展性及隔离责任已保留；具体接口签名属于架构设计，不是待确认产品行为。 |
| 凭据读取与业务调用解耦 | 产品目标、使用者任务链、FR-9、FR-10；FR-7 和首期范围明确本中心不代理业务 API | 已覆盖；CLI 返回业务调用所需凭据，调用者自行调用平台。 |
| 本地开发支持环境变量注入 | 定稿简报“技术与安全约束”；交接补充“已确认约束” | 已覆盖，作为开发配置约束保留。 |
| 生产环境预留专用密钥管理服务边界 | NFR-6、SM-8、Q-9；交接补充“仍待设计”与架构责任表 | 已覆盖；具体后端由架构设计者在对应 Story 编写前确定。 |

## 后续设计边界

尚待确定的适配器接口、密钥后端、Linux 账户与存储权限、审计存储、Token 轮换及真实平台协议，均按 PRD 的角色与复核时点进入架构、CLI 或接入设计。在相应 Story 编写前落实设计及平台依据；这些事项不构成早期输入遗漏，也不将平台联调完成作为 PRD 产品需求基线定稿的前置条件。
