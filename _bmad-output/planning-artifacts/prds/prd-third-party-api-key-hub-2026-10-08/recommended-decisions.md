# 剩余事项推荐清单

用户要求合并剩余问题并给出推荐值，以便一次确认。用户于 2026-10-08 回复“全部采用”，确认 R-1 至 R-9。各项已同步到 prd.md 与验收条件；本清单保留确认依据，后续需求以 PRD 为准。

| 编号 | 事项 | 推荐值 |
| --- | --- | --- |
| R-1 | 成功查询元数据 | 同时返回平台、App、外部店铺、品牌、内部店铺标识，以及凭据类型、状态和有效期；有效期未知须明确标识，不推定永不过期。状态与有效期按具体凭据表达。 |
| R-2 | 成功 JSON 组织 | 采用归属、业务调用凭据、状态／有效期三组结构；对应 App 凭据与店铺 Token 可明确区分，字段名称和平台差异由 CLI 契约设计确定。沿用完整返回与整体失败规则，不包含仅用于刷新或管理授权的凭据。 |
| R-3 | 错误类别 | 使用稳定、可供脚本判断的类别，至少区分输入错误、对象不存在、须指定 App／店铺、归属不完整／不匹配、无权限、必需凭据缺失、过期、停用及内部故障。沿用 error/message 对象，名称由 CLI 契约设计确定，说明不含秘密。 |
| R-4 | 退出码与兼容 | 首期成功为 0，所有失败统一为 1，具体原因看 error；同一主版本中保持已有字段、类型和含义稳定，仅增加兼容的可选字段，破坏性调整升级主版本。 |
| R-5 | App 登记字段与唯一性 | 必填平台、本中心 App 标识和平台侧 App 标识；本中心 App 标识全局唯一，平台＋平台侧 App 标识组合唯一。显示名称可选，平台要求的授权配置与秘密字段由适配器核实。缺少登记所需配置时明确反馈，不虚构平台统一字段。 |
| R-6 | 映射管理字段与冲突 | 使用外部店铺、品牌、内部店铺的稳定标识管理关系，名称仅辅助展示；唯一性冲突拒绝整个变更，原映射不变，不自动抢占或改绑。继续执行已确认的显式变更立即生效规则。 |
| R-7 | 本地停用后的恢复 | 运维重新授权或明确替换导入后，须显式确认恢复取密，并重新满足可用性、完整映射和调用资格条件；后台刷新、验证成功或映射恢复均不能自动解除本地停用。具体确认入口由 CLI 设计确定。 |
| R-8 | 业务调用发现失效后的上报 | 首期通过服务主机 CLI 标记凭据失效，并按已有停用规则拒绝后续取密；本中心不代理业务 API，也不增加远程失效上报接口。平台明确失效证据与暂时故障的分类由接入设计核实，记录不含凭据值。 |
| R-9 | 技术事项的责任与复核 | 架构设计者在对应 Story 编写前落实数据库、生产密钥后端、Linux 目标环境、系统账户权限、审计存储／告警、调度／并发／缓存及必要运行质量目标；CLI 设计者在 CLI Story 编写前落实字段、输入格式、错误编码和兼容契约；平台接入设计者在 TikTok 接入 Story 编写前核实目标市场／App 类型、回调、Token 有效期／轮换、验证与失效分类。后续 Vaultwarden 集成负责人在该集成启动前细化同步范围、条目映射、重试、冲突和撤销传播。以上使用责任角色，不虚构具名负责人。 |

已确认的首期范围、Linux 本地 CLI 边界、明文查询、导入规则、审计要求和后续 Vaultwarden 方向继续以 PRD 为准。平台能力未经核实不作为实现依据。

以上决定已纳入定稿 PRD；决策记录核对、来源对齐和评审已完成。技术细节继续按责任与复核条件交接。
