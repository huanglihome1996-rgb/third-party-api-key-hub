# 定稿简报与 PRD 输入核对

来源：[定稿简报](../../briefs/brief-third-party-api-key-hub-2026-09-29/brief.md)、同目录 `review.md` 与 `.memlog.md`；对照：[PRD](prd.md)、[交接补充](addendum.md)、本工作区 `.memlog.md` 与 [已接受的 R-1 至 R-9](recommended-decisions.md)。本次在全部采用的用户确认之后重新核对，后续用户决定优先于简报中的旧待决。

## 已确认决定的覆盖

- TikTok Shop 首期接入、店铺授权与手工导入并行：FR-1、FR-5、FR-6。
- 平台 App／外部店铺多对多、外部店铺／品牌多对一、品牌／内部店铺双向一对一：术语表及 FR-2 至 FR-4。
- 有权限的可信内部调用者获取完整明文 JSON：FR-9 至 FR-11；后续用户决定将边界收窄为服务主机本地 CLI、受控 Linux 账户，不提供远程取密入口，回调可达性不授予取密资格。
- 真实凭据不得进入源码、Git、日志、测试数据和错误响应：NFR-1 及相关功能验收条件。
- Go 服务与 CLI 共享核心、Linux／systemd、可复现构建、本地环境变量和生产密钥管理服务：交接补充与 NFR-6。
- 钉钉身份验证、更多平台、代理调用、多租户、业务数据同步及独立终端分发均为后续范围：首期与后续边界。

没有发现确认决定被遗漏或被草稿覆盖。`docs/project-brief.md` 是早期输入，旧待确认项不覆盖定稿简报；简报之后的用户决定已通过 PRD `.memlog.md` 留存，不为追求原稿一致而回退已确认规则。

## 后续用户决定与历史替代关系

- 简报 memlog 的“TikTok 仅为示例”、产品线、导入范围、默认明文与访问范围待确认均已被后续用户决定取代，不能恢复为当前事实。
- 简报的完整凭据被细化为业务调用所需完整值；refresh token 等仅用于管理的秘密内部使用，正常查询不返回。业务调用所需 App Secret 仍返回，查询没有改成脱敏。
- 首期撤销已明确仅为本地停用，平台授权由运维另行处理；不能宣称本地停用等于平台撤销，不自动调用平台撤销接口。
- Vaultwarden 自动推送及平台查看权限为新增后续 PF-1／PF-2，有用户决定依据，不扩大首期，不替代生产密钥服务。
- A-1 元数据候选已由 R-1／R-2 确认；查询组合、错误类别、0／1 退出码、主版本兼容、登记字段、映射冲突、显式恢复与本地失效标记均有需求落点。

## 交接与收尾结论

多 App／店铺选择、导入规则、查询输出、访问边界、审计、本地停用和恢复均已确认，不再作为需要逐项追问用户的产品缺口。全部技术事项按 R-9 交接：架构、CLI、平台接入设计者分别在对应 Story 编写前落实；未落实的技术事项不能视为 Story 已可实施。

平台目标市场／App 类型、实际协议、回调校验与可达性、Token 有效期／轮换、验证和失效分类仍须核实。官方资料仅提供线索，不等于实际联调依据；平台撤销接口未核实不阻塞首期本地停用。Vaultwarden 同步细节由后续集成负责人在启动前落实，不阻塞首期。

发现阶段遗留的规则标题、导语、表头及 NFR-2／FR-12 交接措辞已由主任务纠正为已确认规则和技术交接；查询触发即时刷新由架构／接入设计在生命周期 Story 前落实，未暗定策略。当前没有来源或决定遗漏／矛盾需要重新打开用户决策。

本次核对确认输入覆盖，不替代独立 PRD 质量评审、技术设计或平台联调。
